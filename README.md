# Find your food bank (UK)

An interactive map of UK food banks and their donation/collection locations. Tap a pin for the address, phone number, a one-tap Google Maps route, and links to the food bank's own site. Times change, so always call ahead.

Built by Postcode Economics (Dean Goff), [@postcode_economics](https://www.instagram.com/postcode_economics/).

## Data source

Food bank data comes from [Give Food](https://www.givefood.org.uk/) via their public API (https://www.givefood.org.uk/api/). Give Food's terms ask that they are credited and told about projects built on their data; please check https://www.givefood.org.uk/api/ for the current terms. Postcodes are checked with [postcodes.io](https://postcodes.io). Map tiles © OpenStreetMap contributors. Backup map: [OpenFreeMap](https://openfreemap.org) © [OpenMapTiles](https://www.openmaptiles.org/) Data from [OpenStreetMap](https://www.openstreetmap.org/copyright).

## How it updates

Automatic schedules (all times UTC; UK time is UTC+1 in summer, UTC in winter), each also runnable on demand from the Actions tab:

| Workflow | When (UTC) | What it does |
|---|---|---|
| `refresh.yml` | 04:29, 12:29, 20:29 | `scripts/build.py` re-downloads Give Food + IFAN data and food banks' own location pages, removes duplicates, applies `overrides/`; `verify_fresh.py` refuses to publish stale verification; `full_check.py` checks every food bank's own site (hours, closures, access flips, contacts) and writes `reports/daily_review.md`; then `compact.py` writes `data.js` and `stamp.py` stamps the run time. If the download fails or returns fewer than 80% of the current entries, `data.js` is left unchanged. |
| `refresh-shelters.yml` | 04:41, 12:41, 20:41 | Rebuilds `shelters.js`, re-fetching and re-checking every source page. |
| `refresh-warmspaces.yml` | 04:53, 12:53, 20:53 | Rebuilds `warmspaces.js` the same way. |
| `sweep-daily.yml` | 01:00 | Deep sweep of council sitemaps and voluntary-sector lists (adds new entries only). |
| `watchdog.yml` | hourly at :17 | Opens a `refresh-alert` issue if nothing has been published for 10 hours. |

Problems are made visible: a failed run, or a food bank run whose full own-site check failed (the run still publishes the fresh discovery data), opens or updates a GitHub issue labelled `refresh-alert` (`scripts/alert.py`); the next good run closes it. GitHub emails the repository owner about new issues.

## Dates

Every visible date is `26 Oct 2026, 05:55` (UK time, `Europe/London`). A record that has no clock time is the date alone, `26 Oct 2026`. Do not write "today", a long month, or a Welsh month name.

Which source a date uses:

| What the page says | Source | Moves when |
|---|---|---|
| Food banks / shelters / warm spaces "updated", and "Information last updated" on that layer's pages | `stamps/fb.json`, `stamps/sh.json`, `stamps/ws.json` (assembled into `stamp.js`) | that layer's refresh actually publishes |
| Home header "Updated", the FAQ "Map data last checked" line, and the 404 footer | the newest of those three layer stamps | the newest layer refresh |
| "Phone numbers and opening times checked" | `stamps/checked.json` | a full own-site check finishes |
| "Last updated" on the FAQ, terms, privacy and accessibility pages, plus their `dateModified` and sitemap `lastmod` | `overrides/page_dates.json` | that page's own wording changes |
| A card's "checked", "closed" or scheme date, and a rest centre's "open until" | that listing's own field | that listing changes |

Never overwrite another layer's stamp. Each refresh writes only its own file under `stamps/`. `scripts/date_check.py` fails the PR, the refresh, and the deploy check when a data time disagrees across pages, a visible date uses another format, a label is not the stamp time, or a layer's stamp is older than its data file. A failed check does not publish.

Avoid pushing to `main` within a few minutes of a scheduled run: the refresh jobs rebase onto `main` and keep their own generated files (`data.js`, `access.js`, `logs/`, `reports/`) if both sides changed them.

## Overrides

Manual corrections live in `overrides/` and are re-applied on every refresh. Keys are the stable Give Food id shown in `data.js` as `id`:
- a food bank: its Give Food slug, e.g. `"example-foodbank"`
- a location: `"<foodbank-slug>/<location-slug>"`

`overrides/phones.json`:
```json
{ "example-foodbank": "01234 567890" }
```

`overrides/opening_times.json` (free text per entry, or structured if the page supports it):
```json
{ "example-foodbank": "Mon & Thu 10:00-12:00" }
```

## Data files (22 Oct 2026, traffic hardening)
- `data.full.js` is the canonical food bank data (full format). Every script reads/writes it; hand edits go here.
- `data.js` is the compact browser copy, generated by `scripts/compact.py` (build.py, full_check.py and the workflow call it). Never edit it by hand.
- `outcodes.json`: postcode-district centroids, loaded if api.postcodes.io fails or the device is offline; precached by `sw.js` (`scripts/build_outcodes.py`).
- `tiles.js`: provider order is OpenStreetMap (primary, permanent default), then OpenFreeMap (automatic backup: free vector tiles, no key, light Positron style even in dark mode; MapLibre is loaded only when the map falls back). MapTiler is never the default: it is a disabled future fallback with no key. Stadia is not used. Do not put the old MapTiler key back. Proof: `tests/test_tile_fallback.py::Browser::test_osm_blocked_switches_to_openfreemap_and_renders` (CI, stubbed) and the `tile-fallback` job in `deploy-check.yml` (live site, stubbed tiles).
